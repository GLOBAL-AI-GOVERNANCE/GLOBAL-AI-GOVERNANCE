# Maturity Model

Maturity labels communicate what evidence exists today. They are not quality rankings and do not imply certification, compliance, or production authorization.

- **Stable:** the published release is the recommended version; its workflows run end to end within the stated boundary and are tested on every change.
- **Released:** a published release with attested assets that runs end to end within the stated boundary. Open independent reviews are named next to the label.
- **Available:** a published version anyone can use today, with a named independent review or validation still open before a stable release.
- **Specification:** contracts and design are published for review; no execution capability exists until the named review is complete.

Repository-specific language remains authoritative when it is more precise than these portfolio categories.

## Repository maturity is not organizational AI maturity

Repository maturity labels describe the development, release, and evidence status of Global AI Governance repositories.

Organizational AI maturity is a separate Toolkit assessment. A human determines that position under a versioned framework adapter. The Toolkit checks whether submitted evidence can carry the determination.

Neither label is a quality ranking, certification, compliance result, or authorization.
